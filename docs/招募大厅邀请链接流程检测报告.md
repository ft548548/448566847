## 三、完整检测步骤

- **预期**：跳转到招募详情页 `/manage/recruitment/8`，页面渲染标题、队伍、报名区等。

### 步骤 2 · 弹窗出现

### 步骤 3 · 页面跳转到「我的项目」
- 点击「进入项目群聊」或「去项目」；
- **预期**：`goForward` 跳转到 `/manage/project/12`（项目「123」详情页）。

### 步骤 4 · 通过邀请链接加入项目群聊
- 在项目 12 内，由**负责人 test** 通过「更多 → 邀请链接」生成链接；

- 用 **tester 账号**在浏览器打开该链接 → 落地页 `projectInvite.vue` 展示「加入项目」按钮；
- 点击「加入项目」→ 调 `project/invite/join` → 加入成功并同步群聊。

## 四、关键节点（已逐项验证）

| # | 关键节点 | 验证结果 | 接口/证据 |
|---|----------|----------|-----------|
| 1 | 招募详情返回来源项目 | ✅ | `recruitment/one` → `source_project: {id:12, name:123, owner_userid:2, owner_nickname:"tes***@dootask.com"}` |
| 2 | 生成邀请链接 | ✅ | `project/invite` → `url: .../manage/project/invite?code=zGekpzOq...` |
| 3 | 邀请链接查信息 | ✅ | `project/invite/info` → `ret:1`，项目「123」，`already:false` |
| 4 | 通过链接加入项目 | ✅ | `project/invite/join` → `ret:1 加入成功`，`already:true` |
| 5 | 加入后同步项目成员 | ✅ | `pre_project_users` 新增 `(12, 4, 0)` |
| 6 | 加入后同步群聊 | ✅ | `pre_web_socket_dialog_users` dialog 23 由 `[2]` → `[1,2,4]` |
| 7 | 邀请计数 | ✅ | `pre_project_invites.num` 0 → 1 |

**关键机制说明**：`invite__join` 内部调用 `joinProject($userid)` 写入项目成员，再调用 `syncDialogUser()` 全量同步项目成员到群聊（`relationUserids()` 取项目全部成员做 diff）。因此**「加入项目」与「加入群聊」是原子联动**的，还顺带修复了此前 admin 成员未同步进群聊的遗漏。

## 五、可能出现的异常情况（已实测）

| 异常场景 | 触发方式 | 实测结果 | 说明 |
|----------|----------|----------|------|
| 重复加入 | tester 再次用同一 code 调 join | ✅ `ret:1 msg:已加入 already:true` | 幂等，不会重复加成员/计数 |
| 邀请 code 不存在 | 传 `INVALID_CODE_XYZ` | ✅ `ret:0 msg:邀请code不存在` | 正确拒绝 |
| 非负责人获取邀请链接 | admin（项目12普通成员）调 `project/invite` | ✅ `ret:0 msg:仅限项目负责人操作` | 后端 `mustOwner=true` 拦截 |
| 非成员获取邀请链接 | student 调 `project/invite` | ✅ `ret:-4001 msg:项目不存在或不在成员列表内` | 越权拦截 |
| 邀请功能关闭 | 系统设置 `project_invite=close` | 预期 `ret:0 msg:未开放此功能` | 三个接口统一前置校验（当前为 `open`） |
| 来源项目已删除 | `detail.source_project=null` | 前端按钮 `v-if` 隐藏，`goSourceProject` 弹「该项目不存在或已被删除」 | 前端已兜底 |
| 邀请链接被刷新 | 负责人点「刷新」 | 旧 code 立即失效（`invite__info/join` 返回「邀请code不存在」） | 前端有「刷新将导致原链接失效」提示 |
