## 4 网关必须承担的三件事

应用层只做了「兜底校验」，不能替代网关：

1. **覆盖可信头**：客户端传入的 `X-Request-Id`、`X-App-Code` 应由网关重写，不得原样透传；
2. **限流**：按 `X-App-Code` + 来源 IP 限流，超限返回 `429` 并带 `Retry-After`。
   应用层**完全没有限流能力**；
3. **来源校验**：只允许五平台服务身份访问跨平台接口。

应用侧已有：`X-Request-Id` 格式校验（非法则回落新生成）、`X-App-Code` 白名单（非法返回 400）。

## 5 部署检查清单

- [ ] `APP_DEBUG=false`（当前为 `true`，生产必须关闭，否则异常页会暴露堆栈与配置）
- [ ] `APP_KEY` 已设置为随机值且不入库、不入仓
- [ ] `.env` 中数据库密码为强口令，`DB_ROOT_PASSWORD` 不落地
- [ ] MariaDB / Redis 只监听私网或 127.0.0.1
- [ ] Nginx 反代开启 TLS，静态资源走缓存，`client_max_body_size` 与上传上限一致
- [ ] `storage/` 与 `bootstrap/cache/` 权限正确，日志可写
- [ ] 定时任务已配置（DooTask 依赖 `artisan schedule:run` 做归档与通知）
